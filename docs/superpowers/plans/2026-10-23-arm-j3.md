# Arm J3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a published arm J3 mechanism and bidirectional sensitivity page to the existing GitHub Pages site.

**Architecture:** Solve the parallel-axis four-bar in a J3-normal local plane, map the result back to 3D, and compute the rotating pushrod joint velocity from fixed B-end geometry. Reuse the existing page shell, directional-friction helper, contribution charts, and 1 Hz ±10° reporting pattern.

**Tech Stack:** Static HTML/CSS, browser JavaScript, Node.js build and regression tests.

**Spec:** `docs/superpowers/specs/2026-10-23-arm-j3-design.md`

## Global Constraints

- Publish as `arm-j3.html` inside the existing “手臂” module.
- Preserve existing leg pages and use the same visual hierarchy and controls.
- Use 1 Hz, ±10° single-joint excitation.
- Support positive/negative rotational friction and extension/retraction pushrod friction.
- Do not add runtime dependencies.

## Review Focus

- Nominal geometry must reproduce P, Q and fixed-link lengths within numerical tolerance.
- Circle closure must stay on the nominal assembly branch through the full ±10° range.
- Directional friction must switch from the local joint velocity, not merely the sign of J3 velocity.
- Pushrod swing must update its force direction and relative-velocity Jacobian at every pose.
- Existing J2/J3/J4 pages and navigation must remain unchanged except for the new arm entry.
