# J2 Clearance Diagram Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an animated J2 mechanism diagram and a selectable local clearance magnifier to the existing J2 clearance/dead-zone page.

**Architecture:** Extend the existing `J2ClearanceModel` with a presentation-state API that returns nominal and positive/negative contact geometries for one selected interface. Render the full mechanism and local magnifier as SVG in the existing page, driven by the same input state and 1 Hz angle animation used by the calculations.

**Tech Stack:** Buildless HTML, CSS, JavaScript, SVG, Node.js regression tests.

**Spec:** `docs/superpowers/specs/2026-11-03-j2-clearance-diagram-design.md`

## Global Constraints

- Visual displacement is explanatory and must be labeled as magnified; numerical calculations continue to use true millimetre inputs.
- Support axis1, axis2, axis3, point2, and rod as selectable interfaces.
- Preserve the current quasi-static X-Z clearance calculation and existing results.
- Axial passive-joint inputs remain inactive in the two-dimensional model.

## Review Focus

- Zero gaps: nominal and both contact states coincide and the displayed dead-zone is zero.
- Asymmetric gaps: positive and negative contact markers use their respective values and bias direction.
- Rod selection: magnifier changes from radial bearing clearance to axial end-contact presentation.
- Animation reversal: contact side changes with the 1 Hz command direction, not with absolute angle sign.
- Small screens: labels and magnifier remain readable without covering the mechanism.
